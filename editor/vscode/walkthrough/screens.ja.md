# テストケース

テスト設計は、ルールが許していることのすべてを、たどって書き出し、ルールの隣に置いたものです。ここではそれを、アプリケーションそのもののテストケースとして読みます。それぞれ、起動したところから行う手順と、そのあとウィンドウがどうあるべきかで、ルールが断る値もひとつずつテストケースになっています。ひとつ選ぶと、手順をそれぞれのウィンドウで、期待結果(そのあとのウィンドウ、次の操作とその行き先、ここで断られるもの)を見られます。入力する値は **指定値** で試す値を追加できます。違うところがあれば、ふだん使っているエージェントに直すよう頼み、何が変わったかを一覧のいちばん上で読みます。
