# Test cases

The test design is everything the rules allow, walked and written down beside them. Here it is
read as test cases on the application itself: each is the steps to take from where it starts and
what its window should be after them, and each value the rules refuse is one of its own. Choose
one, and you see each step on the window it is taken on, and the expected result: the window, the
next operations and where each leads, and what is refused there. Where a value is typed, add one
to try under **Chosen values**. Where you want something otherwise, ask your agent for it, and
read what the change did at the top of the list.
